# P0 与 P1：作用和体验链路

## P0 的作用：让 Agent 稳定、安全、可追踪地运行

P0 是所有业务 Agent 共用的技术底座：

- FastAPI 接收网页或小程序请求
- 模型网关统一接入模拟模型和 OpenAI-compatible 真实模型
- Pydantic 校验模型结构化输出
- 数据库保存对话、记忆、宠物画像和权威状态
- Prompt 按版本管理
- 记录模型、Token、费用、延迟和错误
- 外发模型请求前对手机号、身份证号和邮箱脱敏
- 自动测试不调用真实模型

P0 不判断用户是什么样的人，也不完成匹配。它相当于 Agent 系统的地基、管道和行车记录仪。

## P1 的作用：孵化一只能够逐步理解主人的宠物

P1 在 P0 上实现第一条业务闭环：

```text
动态访谈
→ 提取候选记忆
→ 用户确认或纠正
→ 发现新旧记忆冲突
→ 判断是否达到孵化条件
→ 生成初生宠物
→ 用户反向验证
→ 将纠正重新写入候选记忆
```

### 动态访谈

访谈 Agent 会读取近期对话和已经确认的记忆，围绕关系目标、偏好、价值观、生活方式和沟通方式选择下一项最有价值的问题。它不会把自己的提问或猜测保存成用户事实。

### 可确认记忆

模型提取的内容首先是 `candidate`。只有用户确认后，状态才变为 `confirmed`。用户也可以纠正、拒绝或删除。

每条记忆包括：

- `memory_key`：稳定主题，例如 `relationship.distance`
- `category`：关系目标、偏好、价值观、生活方式等
- `content`：记忆内容
- `importance`：1–5
- `confidence`：模型提取置信度
- `evidence`：对应的用户原话
- `source_type`：来自访谈还是宠物验证

如果相同 `memory_key` 出现不同内容，新记忆会指出 `conflicts_with_id`。用户确认新内容后，旧内容变为 `superseded`，而不是被静默覆盖。

### 孵化条件

初生宠物至少需要：

- 4 条已经确认或纠正的记忆
- 覆盖关系目标、偏好、价值观、生活方式、沟通方式中的至少 3 类

这只是“初生宠物”条件，不代表宠物已经通过正式红娘上岗审核。

### 宠物画像

宠物生成 Agent 只读取已经确认的记忆，输出：

- 名字、物种和称号
- 三项核心气质
- 关系风格与沟通方式
- 优势与容易被误解之处
- 尚待了解的主题
- 明确保留主人最终决定权的宠物宣言

宠物物种是表达层，不直接用于后续匹配评分。

### 反向验证

用户可以评价画像为：

- `accurate`
- `partly_accurate`
- `inaccurate`

后两种情况必须提供纠正。纠正提取 Agent 会生成新的候选记忆，仍需用户确认，宠物状态变为 `needs_revision`。再次孵化会生成新版本，旧版本保留为 `superseded` 供审计。

## API 体验顺序

在 API 文档 <http://127.0.0.1:8000/docs> 中按顺序调用：

1. `POST /v1/interviews` 创建访谈。
2. `POST /v1/interviews/{session_id}/messages` 对话。
3. `PATCH /v1/memories/{memory_id}` 确认每条候选记忆。
4. `GET /v1/interviews/{session_id}/hatching-readiness` 查看孵化条件。
5. `POST /v1/interviews/{session_id}/pet` 生成宠物。
6. `GET /v1/interviews/{session_id}/pet` 查看当前宠物。
7. `POST /v1/pets/{pet_id}/verification` 进行反向验证。
8. 再次确认纠正产生的候选记忆，并重新孵化宠物。

除创建访谈外，当前演示接口都需要填写 `X-Owner-ID`，且必须与创建访谈时的 `owner_id` 相同。

## 固定评测

运行：

```bash
python -m app.evaluation
```

默认模拟模型会运行 `app/evals/p1_cases.json` 中的固定案例，检查关系目标、硬边界、价值观、生活方式、沟通方式、不确定信息和敏感信息处理。接入真实模型后，同一命令会评测真实模型，便于比较模型或 Prompt 版本。

## 当前不包含

P1 尚未实现：

- 正式上岗测试
- 候选召回与硬条件过滤
- 两只宠物的封闭对谈
- 双向独立裁判
- 真人引荐与聊天

这些功能应在用户确认“宠物能够准确代表自己”后再开发。

## 原型数据库升级说明

P0/P1 仍处于原型期，应用启动时自动建表。如果本地已经运行过旧版 P0 并生成 `agent.db`，拉取 P1 后应先删除这个本地测试数据库，再启动服务。数据库中如已有需要保留的数据，不要删除，应先导出并等待正式迁移脚本。
